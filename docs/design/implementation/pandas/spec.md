# Specification — pandas inspector

**Status:** Accepted for implementation.

A pandas `DataFrame` or `Series` remains a Python object in listener history. A frame click opens a bounded, captured table; its visible column headers and row labels can present positional slices. A series click lists a bounded run of values. This is the complete design input for the checkpoint manager and implementers. They do not need the charter.

## 1. Checkpoint series and authority

The series identity is **pandas**. Checkpoint 000 is spoken **pandas 000** and filed as `checkpoints/000-slug.md`; 001 is **pandas 001**. Numbers have three digits, begin at 000, are never renumbered, and use lowercase hyphenated slugs. The checkpoint manager writes one checkpoint and stops. Each checkpoint implements one independently testable layer: 000 builds the headless pandas model and class registration; 001 appends and draws the rows, routes screen clicks, documents hits, and performs the hand check. A manager may split a layer only when it will not fit comfortably in one implementer conversation; it keeps this order and adds no features. Each implementer receives one checkpoint and stops after it.

After acceptance, this specification is the design authority. It extends the accepted [listener](../listener/spec.md), [REPL](../repl/spec.md), [SymPy](../sympy/spec.md), [HTTP](../http/spec.md), [chips](../chips/spec.md), and [listings](../listings/spec.md) behavior. SymPy governs Python-class registration and retained identity; HTTP governs bounded append-on-click detail; chips governs composition click precedence; listings continues to govern file and process tables. This specification wins only for the row and ordinary click of pandas frames and series, and for the new preview hits. Earlier specifications continue to govern generic values, chips, accepts, and listing commands. [Pandas' positional indexing](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.iloc.html) defines the slice operations below.

## 3. Fixed display contract

These four limits apply to both layers:

| Item | Limit |
|---|---:|
| Visible preview data rows | 12 |
| Visible preview columns | 6 |
| Visible series values | 12 |
| Display cells per preview cell | 16 |

Show the first positions in each axis, with no sort or filter. Every logical row is safely escaped using the listener's `escape_display` rules. Use `truncate_display` so wide and combining characters count in display cells and an ellipsis fits within the limit. Display each axis label with `str(label)`, without a type or repr prefix, and cap it at 24 display cells. If that would display no cells, show `''` so the label has a visible hit. For preview cells and series values, a missing scalar, including `None`, `pandas.NA`, `pandas.NaT`, and numeric NaN, displays as `NA`. Test `pandas.isna(value)` only when it returns a scalar boolean; an array-like result does not make a container cell missing. Other values use their plain `str`: examples are `3`, `2.5`, `True`, and `2024-01-02 00:00:00` for a timestamp. Escape before truncating. A preview cell is capped at 16 display cells, including `…`. A series value row is capped at 120 display cells as a whole, including its positional prefix and any `…`.

The summary rows are exactly `DataFrame R×C`, `Series N NAME DTYPE` for a named series, and `Series N DTYPE` for an unnamed series. `R`, `C`, and `N` are decimal lengths at presentation time. `NAME` is `str(series.name)` if the name is not `None`; `DTYPE` is `str(series.dtype)`. For test fixtures explicitly constructed with those dtypes, an integer series prints `int64`, a string/object series prints `object`, and a nullable Boolean series prints `boolean`. The registered printer returns this raw text; the existing Value path escapes and caps the complete row at 120 display cells. No class repr prefix appears. A row is a fixed drawing, not a live view; evaluating the object again makes a new summary. The summary presentation retains the exact evaluated object by identity, and `_` follows the REPL's existing evaluation rule. A Python chip taken from that summary holds the same object.

## 4. Layer 000 — headless model and registration

Register `pandas.DataFrame` and `pandas.Series` through the existing `ValueClasses` registry. Lookup still walks `type(value).__mro__` and uses the first registered class. Their registrations supply only the summary printers above; they add no translators. Keep the generic printer for all unregistered objects.

Provide pure, headless inspector operations in `src/pbui/pandas_inspector.py`, integrated with `HeadlessListener` in `src/pbui/commands.py` and the class registration in `src/pbui/repl.py`. From a retained frame Value, a headless listener operation captures the preview model without changing `_`; from a retained series Value, another returns its bounded list text without changing `_`. Given a captured preview and a visible integer column or row position, the model returns its cached Series or one-row DataFrame. A headless listener operation presents that cached object as a new Value and sets `_` to it. Invalid source presentations and out-of-window positions produce no extraction. The API names may be chosen in checkpoint 000, but the model must expose the captured snapshot and distinguish column and row selections without looking labels up. Checkpoint 001 uses the same capture, list, cached object, and Value-presentation paths to append history rows and route clicks; it must not recapture the source when a header or label is clicked.

Capture with `frame.copy(deep=True)`. The preview owns that copy; the summary still owns the original frame. At capture, cache each visible selectable column as `snapshot.iloc[:, position].copy()` and each visible selectable row as `snapshot.iloc[[position]].copy()`. A header or row-label hit later carries that already copied `Series` or one-row `DataFrame`. Duplicate labels remain distinct because the integer position chooses each copy. A source reassignment after capture cannot change the captured data or those extracted values; opening another preview of the same summary captures current data. This uses [pandas' `copy(deep=True)` semantics](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.copy.html): arbitrary mutable Python objects stored inside object-dtype cells are not recursively copied. The isolation test changes frame cells through pandas assignment, not by mutating a nested Python object.

For a `Series`, build the text of its first 12 values in positional order at click time. A value row is `[POSITION]  VALUE`, with zero-based decimal `POSITION`; it does not present the scalar. An empty series gives exactly `no values`. After 12 values, append exactly `… (N more values)`, with the omitted count. The list is captured text, so later changes to the series do not alter rows already appended. The list does not change `_`.

The headless tests in `tests/test_pandas.py` cover a fresh namespace without `pandas`; importing it inside the listener; object identity and exact summaries for a frame and named and unnamed series; dtype strings above; ordinary generic rows for a dict, list, and NumPy array; capture isolation after cell assignment and recapture on a second open; positional extraction of the second of two equal-labeled columns; one-row extraction; 12-row and 6-column windows and both omission counts; a 13-value series yielding 12 values and its trailer; missing values and cell truncation; empty series; and no Textual import. They prove that preview capture and series listing leave `_` unchanged, while either extraction sets `_` to the cached copy of the required pandas type. The screen may still use its existing generic drawing at this checkpoint; preview history rows and UI hit routing belong to 001. This layer may edit `src/pbui/pandas_inspector.py`, `src/pbui/repl.py`, `src/pbui/commands.py`, `tests/test_pandas.py`, `pyproject.toml`, and `uv.lock`. It may also edit only the runtime-dependency assertion in `tests/test_terminal.py` so the existing metadata test reflects the added pandas dependency.

## 5. Layer 001 — history rows, hits, and screen

Append the preview after a normal first left click on a retained `DataFrame` summary when no menu, accept, substring accept, or Python composition takes priority. Leave the summary in place and leave `_` unchanged. Repeat clicks append fresh previews, each from the frame's state at that click. A click on a `Series` summary similarly appends its bounded text list, leaves that summary in place, and leaves `_` unchanged. Build and validate all output before appending; if capture or formatting raises, append one existing-style `Error`, append no partial preview/list, and leave `_` unchanged.

The preview is a sequence of logical history rows, never a listing-owned block. Its first row is a table header: literal `index`, then the first at most six column labels. Each data row begins with that row's index label, followed by the corresponding visible cell texts. Left-align fields, pad each field to the maximum displayed width in its visible column, and separate fields with exactly two spaces; omit padding after the final field. The index field is at least the width of `index`. A column field uses the maximum width of its displayed header and visible cells. The per-label and per-cell limits in section 3 apply before widths are measured. Ordinary terminal wrapping may turn a logical row into multiple physical rows; it does not add history rows or enlarge a hit target to adjacent cells.

If both axes have length zero, append only the literal `empty DataFrame`. If there are columns but no rows, append the header and literal `no rows`. If there are rows but no columns, append `index` and one row-label-only row per visible row. If columns were omitted, append literal `… (N more columns)` after the visible data rows, before any omitted-row trailer. If rows were omitted, end with literal `… (N more rows)`. For a frame with columns but no rows and more than six columns, place the columns trailer between the header and `no rows`. These trailers, the empty/no-rows text, all table cells, separators, and the series-list rows are literal content without presentations or chip sources.

When **both** `snapshot.index.nlevels` and `snapshot.columns.nlevels` equal 1, create one `PandasColumn` presentation over each visible header label and one `PandasRow` presentation over each visible row label. These are new exact presentation types, separate from `Value`, and their stored values are the already copied Series and one-row DataFrame from layer 000. The literal `index` corner is inert. The hit covers only the displayed label characters, not the padding or other fields. With a MultiIndex on either axis, show labels as escaped text (including tuple labels via `str`) and create no column or row hits at all. No cell is a presentation. One preview appends at most 15 logical rows (header, 12 data rows, and two trailers, or fewer for empty cases), so it does not by itself evict a source summary that was among the newest 400 history rows. The normal 500-row limit otherwise applies.

A normal first left click on a retained `PandasColumn` or `PandasRow` presentation appends a new `Value` summary for its stored copy. The new Value is a `Series` for a column or a one-row `DataFrame` for a row. It becomes `_` exactly as a new REPL value does. The preview stays in history. Clicking the same header or label again presents that same retained copy in another Value row; it does not reslice the original frame. This click is an extraction, with no menu action or transcript command row.

Preserve click precedence: an open menu handles its own click; a pending presentation or substring accept has its current behavior; a valid Python composition site makes a first left click on a frame summary, series summary, column header, or row label insert a chip of that presentation's stored object. It does not open a preview, list values, or extract. The chip for a preview hit holds its cached copy by identity. An invalid composition site keeps the existing refusal. Later clicks in a click chain do nothing. A cell or other literal preview text does nothing in every mode, including composition. Typed `:show` still does not accept a pandas Value. There is no right-button menu on these presentations.

Update the existing pure documentation formatter in `src/pbui/bottom.py` to identify these targets. In ordinary mode the complete target-first sentences are:

```text
DATAFRAME • Left: show frame preview • Right: no menu
SERIES • Left: list values • Right: no menu
PANDAS COLUMN • Left: take column • Right: no menu
PANDAS ROW • Left: take row • Right: no menu
```

The documentation line may fit or truncate these through its existing width rule. During Python composition, use the chips specification's existing insertion or refusal sentences with these targets. A pending accept uses its existing wrong-type sentence; pandas has no new acceptable type. Multilevel labels, cells, and literal trailers have no target-specific sentence. Keep the existing no-menu response to button 3 or Ctrl-O.

Layer 001 may edit `src/pbui/pandas_inspector.py`, `src/pbui/commands.py`, `src/pbui/repl.py`, `src/pbui/domain.py` for exact presentation types if needed, `src/pbui/bottom.py`, `src/pbui/terminal.py`, `tests/test_pandas.py`, and `tests/test_terminal.py`. It must use the existing `DrawingContext`, `HistoryRow`, and pure-layout fragments so the terminal remains one history surface; it must not create one Textual widget per cell. Its screen test uses `PbuiApp.run_test()`: click a frame summary, the second of two equal-labeled headers, and a row label; prove the returned objects and `_`, then click a cell and prove no action. Also cover a composition click on a header, documentation sentences, a MultiIndex preview with no extraction hits, and the distinction between literal cell space and header/label hits.

## 6. Verification and acceptance

`uv run pytest` is the automated gate. Headless tests must prove all layer 000 behavior plus, after 001, that preview and series-list clicks leave `_` unchanged, an extraction sets `_` to its exact stored copy, the source Value stays retained, a second source click captures later cell changes, all literal rows are inert, both omission trailers have correct counts, and a maximum preview stays within 15 logical rows. The tests construct frames and series locally without Textual or network. Existing tests must continue to pass and `requires-python` remains `>=3.11`.

For the hand check, create and record the absolute path of a disposable directory under the project root, change into it, and run `uv run pbui`. Inside one listener session, `import pandas`, create a small frame with one missing value and two columns sharing a label, evaluate it, and read `DataFrame R×C`. Click the summary and inspect the captured table. Click the second duplicate header and use its Series as a chip in a later expression; click a row label and see a one-row DataFrame; click the Series and read its values. Change a source frame cell and click its old summary again to confirm a fresh preview while the first preview remains fixed. No destructive command is required. The hand check complements the screen test; it is not the automated gate.

Acceptance requires retained pandas identity; fixed, safe summaries; a bounded copy captured at each frame click; positional header and row extraction even with duplicate labels; a bounded, readable series list; no extraction hits for either MultiIndex axis; inert cells and trailers; chip precedence; no pandas menu or colon command; and passing old and new tests. The checkpoint manager writes one checkpoint at a time; each implementer stops after its assigned number.
