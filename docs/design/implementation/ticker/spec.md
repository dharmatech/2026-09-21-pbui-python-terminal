# Specification — ticker and daily price history

**Status:** Accepted and implemented through ticker 001. The focused and full test suites passed; the live AAPL check showed `DataFrame 22×7` with `Close` in the preview.

This series makes one `yfinance.Ticker` a retained listener value and gives it one explicit `history` menu action. That action appends the daily price `DataFrame` returned by the library. This file is the complete design input for the checkpoint manager and implementers; they do not need the charter.

## 1. Checkpoint series and authority

The series identity is **ticker**. Checkpoint 000 is spoken **ticker 000** and filed as `checkpoints/000-slug.md`; 001 is **ticker 001**. Numbers have three digits, start at 000, are never renumbered, and use lowercase words separated by hyphens for the slug. The checkpoint manager writes one checkpoint, then stops. Each implementer receives one checkpoint, implements and tests only that slice, then stops. Code and tests go at the project root, not in this design folder. After user acceptance, this specification is the authority for those conversations.

The order is fixed: **000** adds the library, registers and tests the ticker summary, and proves the injected history operation without Textual; **001** exposes that operation as a menu item, adds documentation and a fixture screen test, performs the live hand check, and writes the demo. Each layer is one independently testable checkpoint. A manager may split a layer only if it cannot fit comfortably in one implementer conversation; it keeps this order and adds no features.

The accepted [pandas specification](../pandas/spec.md) governs every `DataFrame` summary, preview, and positional extraction. The accepted [records specification](../records/spec.md) governs `To JSON records`, including its omission of the index. The accepted [popup specification](../popup/spec.md) and existing listener govern menu geometry, action input rows, replay, click precedence, and generic Value detail. The [HTTP specification](../http/spec.md) supplies the pattern for a single injected operation that tests replace without opening a socket. This specification wins only for the row, target wording, and menu of a `yfinance.Ticker`, and for the new history action. Earlier specifications continue to govern frames, JSON records, generic Values, chips, and accepts.

## 3. Fixed ticker and history contract

Evaluating `yfinance.Ticker("AAPL")` makes one `Value` presentation containing that exact library object and prints `Ticker AAPL`. In general the raw registered printer is `Ticker {value.ticker}`: use the symbol text the object reports, without a second lookup or network request. The existing Value path escapes unsafe characters and caps the whole displayed row at 120 display cells. A chip from the summary holds that same object by identity. An ordinary first left click uses the generic Value detail and never calls the history seam; a valid Python-composition click inserts the ticker chip and never calls the seam. Pending accepts, an open menu, and later clicks in a click chain keep their established priority.

The ticker's only action label is exactly `history`. Choosing it calls the one injected operation on the exact retained ticker. Production calls `ticker.history(period="1mo", interval="1d", timeout=15)`. Pass no `progress` argument because version 1.7.0 does not accept it, and do not write a progress line to standard output. Do not prompt for a period. Opening or hovering the menu does not fetch. The action records the existing `MenuActionInput` row before its result; `run again` uses the saved ticker and operation. A repeat calls the seam again and appends another result.

The injected operation has one argument, the `yfinance.Ticker` object, and returns the `DataFrame` or raises. `HeadlessListener` accepts the callable at construction; its default is the production adapter. It is the only path by which the listener menu fetches ticker history. Tests replace it with a fixture-returning or raising callable, without Textual and without a socket. The headless history operation is callable before the menu is wired, so ticker 000 can prove the behavior. It must validate that the source is a retained ticker Value and must not make an unrelated Value fetchable. Ticker 001 exposes that same operation through the existing Value action route rather than creating a second fetch path.

On success, append the **same** `DataFrame` object returned by the seam as a new Value, set `_` to that frame, and leave the ticker presentation in history, subject only to the existing 500-logical-row limit. The existing pandas summary (`DataFrame R×C`) and preview apply. An empty returned frame succeeds and appears as `DataFrame 0×C` for its actual column count. On a raised exception, append exactly one existing-style `Error`, append no frame, and leave `_` unchanged. The ticker remains. Once the menu is wired in ticker 001, its action input precedes either the frame or the `Error`. A `DataFrame` returned by a user's typed `ticker.history(period="1mo")` also uses the normal pandas Value path, independently of the injected menu seam.

The returned frame's dates stay in its index. `To JSON records` therefore omits dates under the records specification. A user who needs dates as a column can evaluate `reset_index()` in Python before that conversion; this series does not alter the conversion or the frame.
