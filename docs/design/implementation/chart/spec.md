# Specification — ticker candlestick chart

**Status:** Accepted and implemented through chart 001 per user report. The
focused tests passed 108/108 and the full suite passed 505/505. In the live
AAPL check, `candlestick` returned `no prices`; `history` appended a
`DataFrame 22×7` without a chart. Fixture tests cover dated candle hover.

The `candlestick` action on a retained `yfinance.Ticker` appends a character-drawn chart of one month of daily prices to the existing listener history. The chart is one retained object with a nested object for each visible candle. This file is the complete design input for the checkpoint manager and implementers; they do not need the charter.

## 1. Checkpoint series and authority

The series identity is **chart**. Checkpoint 000 is spoken **chart 000** and filed as `checkpoints/000-slug.md`; 001 is **chart 001**. Numbers have three digits, start at 000, are never renumbered, and use lowercase hyphenated slugs. The checkpoint manager writes one checkpoint and stops. Code and tests belong at the project root, never in this design folder.

The accepted [ticker specification](../ticker/spec.md) governs `yfinance.Ticker`, its existing `history` action, and the constructor-injected history seam. The accepted [pandas specification](../pandas/spec.md) governs ordinary `DataFrame` presentation and preview. The [popup specification](../popup/spec.md) governs menu placement, action input, and replay. This specification adds only the `candlestick` action and chart-specific objects, rows, and behavior. ## 3. Fixed chart contract

### 3.1 Action and snapshot

At the end of chart 001, the ticker Value menu has exactly `history`, then `candlestick`. Opening or hovering the menu does not fetch. An ordinary first left click on the ticker retains its existing generic detail behavior and does not fetch; a valid Python-composition click inserts its existing ticker chip and does not fetch. Choosing `history` still calls the injected seam once and appends the returned frame, including an empty frame, without drawing a chart.

Choosing `candlestick` records the existing `MenuActionInput` row, then calls the **same** constructor-injected `ticker_history` callable once on the exact retained ticker. Production continues to call `ticker.history(period="1mo", interval="1d", timeout=15)` through `production_history`; no second Yahoo adapter is added. The headless chart operation can be called before its menu item is wired, but only for a retained ticker Value. Tests inject a local frame or a raising callable, never open a socket, and assert one seam call per choice or replay.

On a valid result, capture the returned rows as immutable chart data sorted by date from oldest to newest, without mutating the frame. Append one chart presentation spanning the entire drawing, set `_` to the chart object, and leave the ticker in history, subject to the existing 500-logical-row limit. Do not append the returned `DataFrame`. A later `history` call, or mutation of the returned frame, cannot change that chart or its candle values. The chart object retains the reported ticker symbol, every captured daily bar, the visible suffix, and the count of older bars omitted from the drawing. Each visible candle is a distinct retained object with its date, open, high, low, and close; a nested `Candle` presentation retains that exact object. There are no candle presentations for omitted days.

An empty frame, missing any of `Open`, `High`, `Low`, `Close`, or an index that is not a `pandas.DatetimeIndex` appends exactly one text row `no prices`, appends no chart, and leaves `_` unchanged. For a coherent chart, reject a frame with `NaT` dates, missing or non-finite OHLC values, or a bar where `Low > High` or any open/close lies outside `[Low, High]`; these also append `no prices` with the same unchanged-`_` behavior. Convert each accepted date to its ISO `YYYY-MM-DD` day and each OHLC value to a finite float when capturing the snapshot. This conversion is chart-local and does not mutate the frame. If the seam raises, append exactly one existing-style `Error`, append no chart, and leave `_` unchanged. All validation and drawing happen before the first chart row is appended, so a bad result never leaves a partial chart. Neither invalid data nor fetch failure removes the ticker. The menu action input, when present, precedes the `no prices`, `Error`, or chart rows.

The saved `candlestick` action retains the original ticker and chart operation for `run again`, including after its ticker row has left history. Replay records a fresh action-input row, calls the same injected seam once, and applies the same success, empty, and exception rules. Route this action as an append operation rather than through the generic Value translator result path: that path would wrongly append the chart as a generic Value and lose its nested candles. Do not alter the saved or replayed `history` action.

### 3.2 Size, scaling, and text drawing

The chart has a fixed **60-display-cell** drawing width. A candle occupies **three adjacent cells**: left tick, stem, right tick. One chart-owned blank cell separates neighboring candles. Thus at most **15** candles fit (`15 × 3 + 14 × 1 = 59`); the final cell is chart-owned padding. Show the most recent 15 bars, ordered oldest at the left. When there are older bars, add exactly one final chart row `… (N more days)`, where `N = total rows − 15`. A 17-row dated fixture therefore shows its last 15 candles and `… (2 more days)`. For 15 or fewer rows there is no trailer. The chart does not reselect its days on terminal resize.

Use **12 plot rows**, with the snapshot's visible bars sharing one price scale. Let `minimum` be the least visible Low and `maximum` the greatest visible High. For a price `p`, compute `q = (maximum - p) * 11 / (maximum - minimum)` and use `floor(q + 0.5)`, clamped to 0 through 11, as its zero-based top-to-bottom plot row. This half-up rule avoids Python's ties-to-even `round`. When `maximum == minimum`, put all four points on row 5. Draw a `│` in the stem cell on every row from the mapped High through mapped Low, inclusive. Draw `─` in the left cell on the mapped Open row and `─` in the right cell on the mapped Close row. If a tick and stem share a row, keep both characters, so equal Open and Close reads `─│─`. Draw all 12 plot rows, including blank cells above or below a particular stem; do not truncate the low or high endpoint. A close equal to the open is rising for color purposes.

The first row is `Ticker SYMBOL`, with `SYMBOL` taken from the ticker's reported `ticker` attribute. Escape unprintable symbol text using the listener's display escaping and truncate the complete title to 60 display cells if necessary. Below the 12 plot rows, draw a horizontal date axis of 60 `─` cells in ordinary history color and one date-label row. The date-label row shows the first visible day at the left and the last visible day at the right in ISO `YYYY-MM-DD` form, with spaces between; for a single candle show its date once. These endpoint labels identify the time direction, while hovering any candle names its exact date. Title, plot rows, axis, date labels, and optional trailer are all padded or bounded to 60 display cells and belong to the one outer `Chart` presentation. The chart has 15 logical rows without a trailer and 16 with one. It is a sequence of `HistoryRow` values in the existing history surface, not a separate widget or window. Normal two-cell history indentation, ordinary viewport cropping, and the 500-row retention limit still apply; the fixed drawing may wrap in a terminal narrower than 62 cells, and hit testing follows the actual `layout` intervals.

On every plot row, wrap each visible candle's complete three-cell block in its nested `Candle` presentation, including blank cells within that block. Reuse that day's same presentation on all 12 plot rows. The one-cell gaps, title, axis, date labels, padding, and trailer belong only to the chart. The outer chart fragment covers every drawn cell of every row. The existing pure layout must produce separate `DisplayInterval`s for each candle's columns on each physical row. The deeper candle wins `hit_test` in any of its three columns; a gap returns the chart. The date labels return the chart. A fixture layout at least 62 cells wide must prove these hits, including a candle's blank plot cell and the gap next to it. No per-character color fields or one-widget-per-candle implementation is added.

### 3.3 Clicks, hover, and documentation

With no input waiting, an ordinary first left click on a candle appends one text detail row, `YYYY-MM-DD • Open O • High H • Low L • Close C`, using the captured values' ordinary float strings (for example `10.0`). It leaves the chart in history and leaves `_` unchanged. Repeated clicks may append repeated detail rows. A left click on the chart outside candle blocks appends nothing and leaves `_` unchanged. During valid Python composition, a first left click on a candle inserts a chip containing that exact candle object; a click on chart-only cells inserts a chip containing the chart object. These clicks append no detail. Give those chips concise labels `Candle YYYY-MM-DD` and `Ticker SYMBOL chart`, respectively, rather than deriving a label from a blank plot row. An invalid composition site keeps the listener's existing refusal. Open-menu, pending-accept, substring-accept, and click-chain precedence stay as they are. Neither object is an accept target or has a right-button menu.

In ordinary mode the complete target-first documentation sentences are:

```text
CANDLE 2026-09-21 (rose) • Left: show • Right: no menu
CANDLE 2026-09-22 (fell) • Left: show • Right: no menu
CHART AAPL • Left: no action • Right: no menu
```

Substitute the captured date or safely escaped reported symbol. `rose` means `Close >= Open`, including a flat day; `fell` means `Close < Open`. During valid Python composition, use `Left: insert value into expression`; use the existing insertion-refusal wording for an invalid site. A pending accept uses the existing wrong-type wording and cancel suffix, with `Candle` or `Chart` as the type; neither receives acceptable-target green. The documentation line retains its existing fitting and truncation behavior. Hovering a candle reverses only that candle's three-cell blocks on its 12 plot rows, leaving other candles, gaps, axis, and labels un-reversed. Hovering chart-only cells names the chart and follows the ordinary outer-presentation hover rule. Outside accept, set each whole rising candle to green `#00d787` and each whole falling candle to red `#ff5f5f`; the chart's title, axis, labels, gaps, and trailer use ordinary history color. Pending accept keeps the listener's inert dim-gray treatment. These styles apply to presentation intervals, not to every history character.
